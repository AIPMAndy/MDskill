## 📝 场景 1: 日常写作（权重 40%）

### 实际流程
```
1. 打开应用
2. 看到欢迎弹窗（首次）
3. 开始写作 2000 字技术文章
4. 保存文档
5. 第二天继续编辑
```

### 体验评分: 75/100

#### ✅ 做得好的地方

1. **字体大小优化** ⭐⭐⭐⭐⭐
   - 16px 默认字体，看着舒服
   - Cmd+/- 可以调节，很方便
   - **评价**: 这个优化太需要了！

2. **字数统计** ⭐⭐⭐⭐⭐
   - 状态栏实时显示字数和字符数
   - 写作时能掌控篇幅
   - **评价**: 这是写作工具的基本配置，做对了

3. **自动保存提示** ⭐⭐⭐⭐
   - 显示"Saved Xs ago"
   - 不再担心丢失内容
   - **评价**: 安全感提升

4. **实时预览** ⭐⭐⭐⭐⭐
   - 编辑器和预览同步流畅
   - 排版效果实时可见
   - **评价**: 这是核心优势

#### ❌ 严重影响使用的问题

**P0-1: 没有最近文档列表** 🔴
- **问题**: 每次都要"打开文件"然后浏览文件夹
- **场景**: 每天要打开昨天的文件，需要点 3-4 次
- **期望**: 菜单栏"文件 → 最近打开"，显示最近 10 个文件
- **影响**: 每天浪费 1-2 分钟，累计很烦
- **实现难度**: 低（读取系统最近文档 API）
- **是否加功能**: 否，这是标准编辑器功能

**P0-2: 图片插入太麻烦** 🔴
- **问题**: 
  1. 截图后需要先保存到硬盘
  2. 手动输入图片路径
  3. 如果路径错误，图片不显示
- **场景**: 写技术文章需要插入 10+ 张截图
- **期望**: 
  - Cmd+V 直接粘贴图片
  - 自动保存到文档同目录的 `images/` 文件夹
  - 自动插入正确的相对路径
- **影响**: 插入图片时间从 30 秒降到 3 秒
- **实现难度**: 中
- **是否加功能**: 否，这是 Markdown 编辑器标配

**P0-3: 没有文档大纲/目录** 🔴
- **问题**: 写长文档时（3000+ 字）无法快速跳转
- **场景**: 需要修改第 5 个章节，要滚动半天才找到
- **期望**: 
  - 右侧显示文档大纲（H1/H2/H3）
  - 点击标题直接跳转
  - 可以折叠/展开
- **影响**: 长文档编辑效率太低
- **实现难度**: 中（需要解析 Markdown，监听滚动）
- **是否加功能**: 否，这是长文档编辑的刚需

#### ⚠️ 明显不方便的问题

**P1-1: 编辑器没有行号**
- **问题**: 讨论文档时无法引用"第 X 行"
- **场景**: Code Review 时需要指出具体行
- **期望**: 左侧显示行号（可选）
- **影响**: 团队协作不便
- **实现难度**: 低

**P1-2: 没有查找替换快捷键**
- **问题**: 只能用系统的 Cmd+F，功能弱
- **场景**: 需要把文章中所有"机器学习"改成"深度学习"
- **期望**: 
  - Cmd+F 打开查找框
  - Cmd+Option+F 打开查找替换
  - 支持正则表达式
- **影响**: 批量修改不方便
- **实现难度**: 中

**P1-3: 没有撤销历史**
- **问题**: 只能 Cmd+Z 一步步撤销，无法跳到某个历史版本
- **场景**: 改了半天发现改坏了，想回到 1 小时前
- **期望**: 类似 Git 的历史记录
- **影响**: 大幅修改时焦虑
- **实现难度**: 高

**P1-4: 代码块没有行号**
- **问题**: 代码块是纯文本，讨论代码时无法引用
- **场景**: 技术博客需要解释代码逻辑
- **期望**: 代码块自动显示行号
- **影响**: 技术写作体验
- **实现难度**: 低（CSS + marked.js 配置）
