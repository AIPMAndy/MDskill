# MDskill 安全构建指南

## 安全加固措施

### 1. 代码混淆
- 使用 `javascript-obfuscator` 对关键代码进行混淆
- 混淆强度：高（包括控制流平坦化、死代码注入、字符串加密等）
- 保护文件：
  - `license-manager.js` - 授权管理
  - `activation-code-generator.js` - 授权码生成
  - `subscription-manager.js` - 订阅管理

### 2. 完整性检查
- 在运行时验证关键文件是否被篡改
- 使用 SHA-256 哈希值验证文件完整性
- 如果检测到篡改，授权验证将失败

### 3. 反调试保护
- 检测是否在调试器中运行
- 检测开发者工具是否打开
- 自我防御代码（修改后无法运行）

## 构建命令

### 普通构建（开发用）
```bash
npm run build:mac
```

### 安全构建（发布用）⭐
```bash
npm run build:secure
```

**安全构建流程**：
1. 备份原始文件到 `.backup/` 目录
2. 混淆关键代码
3. 生成完整性哈希
4. 打包应用
5. 恢复原始文件（保持开发环境干净）

### 手动混淆（测试用）
```bash
npm run obfuscate
```

## 使用建议

### ✅ 发布版本
- **必须使用** `npm run build:secure` 构建
- 混淆后的代码难以阅读和修改
- 包含完整性检查和反调试保护

### ⚠️ 开发版本
- 使用 `npm run build:mac` 或 `npm run dev`
- 代码未混淆，便于调试
- **不要发布给用户**

## 安全级别

当前实施的保护措施：

| 保护措施 | 级别 | 说明 |
|---------|------|------|
| 代码混淆 | ⭐⭐⭐⭐ | 高强度混淆，难以逆向 |
| 完整性检查 | ⭐⭐⭐ | 检测文件篡改 |
| 反调试 | ⭐⭐⭐ | 检测调试器和开发者工具 |
| 自我防御 | ⭐⭐⭐⭐ | 代码修改后无法运行 |

**总体安全级别**: ⭐⭐⭐⭐ (高)

## 局限性

⚠️ **重要提示**：
- 客户端保护无法做到 100% 防破解
- 技术高手仍可能通过以下方式破解：
  - 修改 Electron 运行时
  - Hook 系统调用
  - 内存修改
  - 重新打包应用

如需更高安全性，建议：
- 实施在线授权验证（服务器端验证）
- 定期更新混淆算法
- 添加行为分析（检测异常使用模式）

## 故障排除

### 构建失败
```bash
# 恢复原始文件
cp .backup/*.js .

# 重新构建
npm run build:secure
```

### 授权验证失败
- 检查是否使用了安全构建版本
- 确认完整性哈希已正确生成
- 查看控制台是否有 `[Security]` 错误信息
