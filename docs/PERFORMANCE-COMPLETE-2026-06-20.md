#### ✅ 3. 调试日志系统优化

**问题**：生产环境中大量 `console.log` 影响性能
- `renderer.js`: 52 个调试日志
- `wechat-renderer.js`: 5 个调试日志
- `copy-utils.js`: 5 个调试日志

**解决方案**：添加 DEBUG 模式开关
```javascript
const DEBUG = process.env.NODE_ENV === 'development';
const log = DEBUG ? console.log.bind(console) : () => {};
const warn = DEBUG ? console.warn.bind(console) : () => {};
```

**效果**：
- ✅ 生产环境自动禁用所有调试日志
- ✅ 减少不必要的函数调用
- ✅ 提升启动和运行性能

### 第三阶段：性能优化 Phase 1（2026-06-20 下午）

#### ✅ 6. 主题懒加载系统（预计提升 300-500ms）

**问题**：
- `templates.js` 有 1,837 行代码，包含 33 个主题完整定义
- 启动时全部加载，但用户只使用 1 个主题
- 浪费率：97%

**解决方案**：
1. 创建 `templates-index.js` (54行) - 只存元数据
2. 创建 `templates-loader.js` (195行) - 懒加载逻辑
3. 启动时只加载当前使用的主题
4. 其他主题按需异步加载
5. 内存缓存已加载的主题

**效果**：
- ✅ 启动时只解析 ~50 行主题代码（减少 97%）
- ✅ 内存占用减少 ~1.5MB
- ✅ 启动时间预计减少 **300-500ms**

---

#### ✅ 7. 模块延迟加载（预计提升 100-200ms）

**问题**：
- 18 个 JS 文件在启动时同步加载（~10,493 行代码）
- 很多模块在启动时不需要

**解决方案**：

**立即加载**（核心模块，10个）：
- i18n-helpers.js
- templates-index.js
- templates-loader.js
- renderer.js
- toolbar-i18n.js
- document-search-i18n.js
- document-search.js
- find-replace.js
- line-numbers.js
- command-palette.js

**延迟加载**（1秒后，4个）：
- welcome-modal.js
- trial-reminder.js
- theme-preview.js
- debug-theme.js

**按需加载**（点击时，3个）：
- wechat-renderer.js + wechat-preview-modal.js（点击"复制到微信"时）
- copy-utils.js（点击"复制到博客"时）
- pdf-export-progress.js（点击"导出PDF"时）

**效果**：
- ✅ 启动时只加载 10 个核心模块（~6,000 行）
- ✅ 8 个非核心模块延迟或按需加载（~4,500 行）
- ✅ 启动时间预计减少 **100-200ms**

---

#### ✅ 8. localStorage 批量读取优化（预计提升 10-15ms）

**问题**：
- localStorage.getItem 分散在多处
- 同一配置项被重复读取

**解决方案**：
1. 创建 storageCache 缓存对象
2. `loadStorageCache()` - 一次性批量读取所有配置
3. `getCachedItem()` - 从缓存读取
4. `setCachedItem()` - 写入时同步更新缓存

**效果**：
- ✅ 启动时批量读取，减少系统调用
- ✅ 缓存后续读取，避免重复访问
- ✅ 启动时间预计减少 **10-15ms**
